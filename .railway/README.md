# 🚂 Railway ডিপ্লয়মেন্ট (Infrastructure as Code)

`xtream-proxy` Railway-তে চালানোর অফিসিয়াল কনফিগ — `.railway/railway.ts` ফাইলে
প্রজেক্ট ও সার্ভিস পুরোপুরি ডিফাইন করা। Railway এখন এই **IaC** ফরম্যাটকেই রেকমেন্ড
করে; পুরনো `railway.json`/`railway.toml` ("Config as Code") ডেপ্রিকেটেড।

## ✨ Railway-অপ্টিমাইজড কী কী

| বিষয় | সেটিং | কেন |
|---|---|---|
| বিল্ড | `DOCKERFILE` + `rootDirectory: xtream-proxy` | মাল্টি-স্টেজ, স্ট্যাটিক Go বাইনারি, নন-রুট ইউজার — ছোট ইমেজ, ক্যাশেবল লেয়ার |
| পোর্ট | Railway-র `PORT` env | অ্যাপ নিজেই `PORT` env সম্মান করে (config.go) — আলাদা কিছু লাগে না |
| হেলথচেক | `/status` | ক্রেডেনশিয়াল ছাড়াই সবসময় 200 → ডিপ্লয় রোলব্যাক হয় না |
| রিস্টার্ট পলিসি | `ALWAYS` | ক্র্যাশ হলে নিজে থেকেই উঠে দাঁড়ায় |
| রেপ্লিকা | `1` | ফ্যান-আউট হাব প্রতি-প্রসেস স্টেট — হরাইজন্টাল স্কেল অর্থহীন |
| ডিপ্লয় | overlap 20s + draining 30s | জিরো-ডাউনটাইম + গ্রেসফুল শাটডাউন সম্পন্ন হওয়ার সুযোগ |
| ক্রেডেনশিয়াল | ড্যাশবোর্ড Variables (`preserve()`) | সিক্রেট কোড/ফাইলে লিক হয় না, IaC ওভাররাইটও করে না |

## 🚀 ডিপ্লয় (CLI + IaC) — রেকমেন্ডেড

প্রয়োজন: [Railway CLI](https://docs.railway.com/cli) (`npm i -g @railway/cli`) ও Node ≥ 22।

```bash
# ১. IaC নির্ভরতা (railway SDK) — রিপোজিটরি রুটে, একবারই
npm install

# ২. Railway-তে লগইন ও প্রজেক্ট/এনভায়রনমেন্ট লিংক
railway login
railway link

# ৩. কী কী তৈরি/বদলাবে দেখুন (নিরাপদ — কিছুই অ্যাপ্লাই হয় না)
railway config plan

# ৪. প্রয়োগ করুন (ইন্টারঅ্যাক্টিভ নিশ্চিতকরণসহ)
railway config apply
```

এরপর **ড্যাশবোর্ড → আপনার সার্ভিস → Variables**-এ এই তিনটি ভ্যালু বসান
(রিডিপ্লয় নিজে থেকেই হয়ে যাবে):

| ভ্যারিয়েবল | বিবরণ |
|---|---|
| `XTREAM_BASE_URL` | Xtream সার্ভারের বেস URL, যেমন `http://source-server.com:8080` |
| `XTREAM_USERNAME` | Xtream ইউজারনেম |
| `XTREAM_PASSWORD` | Xtream পাসওয়ার্ড |

> `PORT` **সেট করবেন না** — Railway নিজেই ইনজেক্ট করে। `XTREAM_*` ফাইলে না লিখে
> ড্যাশবোর্ডে রাখুন; `.railway/railway.ts`-এর `preserve()` গ্যারান্টি দেয় যে
> পরের `railway config apply`-তেও ভ্যালু অক্ষত থাকবে (সিল/এনক্রিপ্টও করতে পারেন)।

এখনই ব্যবহারযোগ্য:

```
https://<আপনার-সার্ভিস>.up.railway.app/        → ল্যান্ডিং পেজ
https://<আপনার-সার্ভিস>.up.railway.app/status  → লাইভ ড্যাশবোর্ড (হেলথচেকও এটি)
https://<আপনার-সার্ভিস>.up.railway.app/live/<stream_id>  → রেস্ট্রিমিং URL
```

## 🖱️ বিকল্প: ড্যাশবোর্ড থেকে ম্যানুয়াল ডিপ্লয়

IaC/CLI ব্যবহার না করলে:

1. Railway ড্যাশবোর্ড → **New Project → Deploy from GitHub repo** → এই রিপো বাছুন।
2. সার্ভিস সেটিংসে **Root Directory = `xtream-proxy`** দিন — Railway তখন
   `xtream-proxy/Dockerfile` নিজেই ডিটেক্ট করে বিল্ড করবে (বিল্ড কনটেক্সটও ওই ফোল্ডার)।
3. **Settings → Networking → Healthcheck Path** = `/status`, Timeout = 180।
4. **Variables**-এ উপরের ৩টি `XTREAM_*` ভ্যালু বসান → Deploy.
5. **Restart Policy** = Always, **Replicas** = 1 রাখুন।

## ❤️ হেলথচেক ও গ্রেসফুল শাটডাউন

- Railway `/status`-এ GET করে; এটি ক্রেডেনশিয়াল সেট না থাকলেও 200 দেয় —
  ফলে ভুল কনফিগে ডিপ্লয় আটকে যায় না, বরং লগে
  `⚠️ Xtream ক্রেডেনশিয়াল সেট করা নেই!` দেখায়।
- ডিপ্লয়/স্কেল-ডাউনের সময় Railway **SIGTERM** পাঠায়। অ্যাপটি সব ভিউয়ার ও
  আপস্ট্রিম সংযোগ পরিষ্কারভাবে বন্ধ করে (১০ সেকেন্ড) — `drainingSeconds: 30`
  সেট থাকায় SIGKILL তার আগে আসে না।
- `overlapSeconds: 20` — নতুন ইন্সট্যান্স সুস্থ না হওয়া পর্যন্ত পুরোনোটা
  চলতে থাকে → লাইভ স্ট্রিমে ডিপ্লয়-জনিত ড্রপ নেই।

## 📈 স্কেলিং ও খরচ নোট

- **রেপ্লিকা ১-ই রাখুন।** `/live/<id>` ফ্যান-আউট হাবের ভিউয়ার-লিস্ট ও আপস্ট্রিম
  কানেকশন প্রতি-প্রসেস; ২টি রেপ্লিকা মানে ২টি আলাদা আপস্ট্রিম কানেকশন ও আলাদা
  ড্যাশবোর্ড। ভিউয়ার বাড়লে Railway-তে **vertical স্কেল** (CPU/RAM) করুন —
  প্রসেস মডেল বদলায় না।
- Railway **egress-ভিত্তিক বিল** করে। স্ট্রিমিং প্রক্সি মানে বেশি আউটবাউন্ড
  ডেটা — খরচের দিকে নজর রাখুন। `/live/` ফ্যান-আউট অন্তত আপস্ট্রিম দিকের ট্রাফিক
  (১ কানেকশন → N ভিউয়ার) বাঁচায়; ভিউয়ার-মুখী ইগ্রেস অনিবার্য।
- **রিজিয়ন** আপস্ট্রিম Xtream সার্ভারের সবচেয়ে কাছেরটা বেছে নিন
  (`.railway/railway.ts`-এ `region` কমেন্ট খুলে, বা ড্যাশবোর্ড Settings-এ) —
  প্রথম মাইল লেটেন্সি সরাসরি স্ট্রিম স্টার্ট-টাইমে পড়ে।

## 🤖 CI/CD — GitHub Actions

`.github/workflows/railway-deploy.yml` রেডি করা: `.railway/` বদলানো PR-এ **plan**
(কমেন্টে ডিফ), মার্জে **apply** — রিভিউ করা প্ল্যানটাই ল্যান্ড হয়।

চালু করতে Railway-তে একটি [Project Token](https://docs.railway.com/integrations/api#project-token)
বানিয়ে GitHub রিপো সিক্রেট `RAILWAY_TOKEN`-এ রাখুন। টোকেন না থাকলে ওয়ার্কফ্লো
নিজে থেকেই স্কিপ করে — অন্য CI ভাঙে না।

## 🧪 ডেমো স্ট্যাক (লোকাল/CI-তেই রাখুন)

নকল আপস্ট্রিম (`upstream-sim`) লোকাল ও CI এন্ড-টু-এন্ড টেস্টের জন্য —
Railway-তে এর দরকার নেই, শুধু প্রোডাকশন প্রক্সিটাই ডিপ্লয় হয়:

```bash
docker compose --profile demo up -d --build   # লোকাল এন্ড-টু-এন্ড টেস্ট
```

## 🔐 নিরাপত্তা নোট

- Railway ডিফল্টে **পাবলিক URL** দেয়। `/hls/<id>/u/<base64>` পাথ যেকোনো http(s)
  URL প্রক্সি করতে পারে (SSRF-প্রবণ) — পাবলিকলি এক্সপোজ করলে অবশ্যই
  অথেন্টিকেশন/ফায়ারওয়াল লাগান, নাহলে শুধু বিশ্বস্ত ক্লায়েন্টকেই URL দিন।
- `XTREAM_PASSWORD` ড্যাশবোর্ডে **sealed** করে রাখতে পারেন — প্ল্যান/লগ আউটপুটে
  ভ্যালু কখনো প্রিন্ট হয় না (`«hidden»` দেখায়)।
- রিরাইট করা m3u8-এ আপস্ট্রিম ক্রেডেনশিয়াল ক্লায়েন্টে যায় না (CI টেস্টে ভেরিফাইড)।
